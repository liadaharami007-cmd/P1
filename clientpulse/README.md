# ClientPulse OS — מערכת הפעלה למשרדי פרסום (בתוך P1)

כתובת: `http://localhost:8000/pulse` (אותו שרת, אותו חשבון ואותה התחברות כמו P1).
המקור: ClientPulse 2.0 (Artifact, קובץ HTML יחיד בדפדפן) — נשמר כגיבוי ב-`clientpulse/legacy/` ובתגית git `backup/before-clientpulse-os`.

## מה נבנה
| שכבה | קובץ | מה עושה |
|---|---|---|
| מנוע רמזור | `app/pulse/engine.py` | זינוק עלות לליד (מבחן סטטיסטי מול ההיסטוריה), אפס לידים (הסתברות פואסון), הוצאה בלי לידים, ירידת CTR, ירידת המרה, מגמת הידרדרות (רגרסיה שבועית), חריגה מיעד, לידים בלי מכירות (רק כשיש נתוני מכירות), נתונים חסרים, שיפור מובהק. ציון בריאות שקוף, ספים לכל לקוח, חקירה: עובדות / השערות / בדיקות / תוכנית / מדד הצלחה. הזדמנויות, אינדיקציית סיכון, רווחיות. |
| תפעול | `app/pulse/service.py` | מחזור חיים של התראה (חדשה / החמירה / בטיפול / נפתרה / חזרה לתקין / שווא), משימות עם אישור מנהל לפעולות רגישות, בדיקה חוזרת אוטומטית, 9 אוטומציות עם יומן ריצות + מניעת כפילות + ניסיון חוזר + בדיקה יבשה, הוכחת ערך, עומס צוות, Demo Lab, ייבוא CSV. |
| נתונים | `app/pulse/store.py` | טבלאות `pulse_*` באותו SQLite, הכול מסונן לפי `account_id`. |
| סוכן | `app/pulse/ask.py` | Ask ClientPulse: כוונה → שליפת נתונים → תשובה + ראיות + קישורים. כשיש מודל (Gemini / Claude / Ollama) הוא רק מנסח מחדש מתוך העובדות. |
| תזמון | `app/pulse/scheduler.py` | בדיקה יומית בשרת (מה-worker), פעם ביום לכל סוכנות. |
| דוחות | `app/pulse/report.py` | דוח ללקוח + דוח שבועי (HTML ממותג, PDF דרך Chromium). |
| ממשק | `app/static/pulse/` | מרכז פיקוד ("מה עושים היום?"), לקוחות, תיק לקוח 360 עם גרף וציר זמן, משימות ואישורים, Ask, הזדמנויות, רווחיות, צוות, הוכחת ערך, דוחות, אוטומציות, חיבורים, Demo Lab, סיור "חמש דקות בחיים של מנהל משרד", חיפוש ⌘K, כהה / בהיר, מותאם לאייפון. |
| בדיקות | `tests/test_pulse.py` | 15 בדיקות: מנוע, חלוקה באפס, נתונים חסרים, מסלול מלא מקצה לקצה, אוטומציות בלי כפילויות, הפרדת חשבונות, CSV, Ask, תזמון. |

## מה אמיתי ומה דמו
- **אמיתי:** המנוע, ההתראות, המשימות, האישורים, הבדיקות החוזרות, האוטומציות והתזמון, ההרשאות (בעלים / מנהל מאשרים), הפרדת הסוכנויות, הדוחות, ייבוא CSV של נתונים אמיתיים.
- **דמו (מסומן "דמו" בכל מקום):** 50 לקוחות עם 90 ימי היסטוריה מדומה, שעון דמו, תרחישים, "סימולציית תיקון".
- **לא מחובר (מוצג ככזה, עם מה שחסר):** Meta Marketing API, Google Ads API, CRM, WhatsApp Business, Email. הסוכן משתמש במודל AI רק אם מוגדר מפתח בשרת.

## הרצה
```bash
. .venv/bin/activate && uvicorn app.main:app --port 8000   # → http://localhost:8000/pulse
python -m pytest -q tests/test_pulse.py
```
פתחו חשבון → "הפעל סביבת דמו" → "חמש דקות בחיים של מנהל משרד".
לקוח אמיתי: "+ לקוח" → בתיק הלקוח "ייבוא נתונים (CSV)" (ייצוא יומי מ-Meta / Google: date, spend, impressions, clicks, leads; אופציונלי: sales, revenue).

## הצעד הבא (לפי ערך)
1. מתאם Meta Marketing API (Insights יומי לכל חשבון מודעות) — דורש אפליקציית Meta + ads_read. כותב לאותה טבלה `pulse_days`.
2. Google Ads API (developer token + OAuth).
3. CRM / Webhook ללידים — איכות לידים, שיעור סגירה, CAC, ROAS.
4. שליחת התראות פנימיות ב-WhatsApp / Email (אחרי חיבור, באישור).
5. משתמש-צופה ללקוח (פורטל קריאה בלבד) והרשאות לפי לקוח לעובדים.
6. Postgres + worker נפרד לפריסה מסחרית.
